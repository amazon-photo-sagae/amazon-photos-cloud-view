# 寒河江ボーイズ PHOTO & MOVIE

Amazon Photosの共有アルバムを写真一覧として表示し、YouTubeの動画リンクを案内するアプリです。Node.js、Express、Playwright Chromiumを使用しています。

## 保存データ

| 保存場所 | 内容 |
| --- | --- |
| `/data/galleries.json` | アルバム登録情報（日付、大会名、対戦相手、共有URL） |
| `/data/gallery-cache.json` | 画像URLと取得日時のキャッシュ |
| `/data/current-gallery.txt` | 保存中のアルバムURL |
| `server.js` の `/movie` 処理 | 動画リンクと表示情報 |

写真・動画の本体はAmazon Photos・YouTube側にあります。これらのファイルはリンクや表示情報を保存します。保存先とJSON形式は今回の修正でも維持しています。アプリの起動時にデータを初期化する処理はありません。

Volumeの削除・付け替え・マウント先変更、データの初期化は通常のコード更新に不要です。既存Volumeを維持してください。

## 2026年10月14日の不具合修正

写真登録時にChromium起動の `spawn EAGAIN` が発生していました。登録、キャッシュ切れ閲覧、テスト経由の取得がそれぞれブラウザーを起動し、同時実行を制限していませんでした。OSのプロセス・スレッド上限への到達が最有力でしたが、発生時のRailway上限・イベントを取得できていないため、根本原因の実測による確定はしていません。

- 修正コミット：`d82d67804e7be032fdfeb28810fd918c38716e0e`
- 本番へ反映したPR：[#1](https://github.com/amazon-photo-sagae/amazon-photos-cloud-view/pull/1)
- マージコミット：`2968a39598545bec70e1d05c8d1ffb3a008a8e3d`
- 修正前のコード：`c44c1f764dfbbcce4ff790fd877671122f5239d7`

主な変更：

1. 登録と閲覧を共通キューにまとめ、Nodeプロセスごとに同時ブラウザーを1件に制限。処理中・待機中は合計6件まで。同じ共有URLの取得は共有します。
2. ブラウザーの終了を待ってから次を実行。終了失敗時は追加起動を止めます。
3. キャッシュがある閲覧は先に表示し、期限切れなら裏で更新。強制更新失敗時にも保存済みキャッシュへ戻します。
4. 写真0件や取得失敗で正常なキャッシュを上書きしません。
5. 同一ディレクトリ内の一時ファイルとrenameで、ファイルごとの書き込みを保護。既存JSONの読み込みに失敗した場合は上書きを停止します。
6. 取得時のフォント・メディア通信を抑制。画像とスクリプトは有効に保ちます。取得のタイムアウトとPID・メモリの診断ログを追加しました。
7. `/test` に管理者認証を追加。通常の写真閲覧は公開のままです。

既存の動画ページとリンク、Dockerfile、依存関係は変更していません。詳細・制約は [REPAIR-NOTES.md](REPAIR-NOTES.md) を参照してください。

## 次回トラブル対応

1. プロジェクト、環境、公開ドメイン、デプロイコミット、既存Volumeの `/data` 接続を照合します。
2. ログ、データファイルの存在・サイズ・JSONの読み込みを調べます。秘密情報の値を表示・共有しません。
3. 最新データを読み取り専用でPCへコピーし、SHA-256と展開後の一致を検証します。Windows PowerShellではSSH出力をBase64文字列で取得し、元のバイト列へ戻す方法を使用しました。`railway shell` はローカルのシェルであり、稼働コンテナへ接続する `railway ssh` とは異なります。
4. 修正は別ブランチでテストします。`main` の変更は自動公開を起こすため、公開許可前にマージしません。
5. 公開後は既存PHOTO・MOVIEを先に確認し、その後、許可された新規登録を確認します。
6. 問題があれば状況を報告し、無断でデータ復元・削除・Volume変更を行いません。

元のプログラムへ戻す場合、PR #1にはGitHubのRevert操作が表示されました。これは取り消し用PRを作るための入口です。対象コミットを確認し、取り消し用PRをレビュー・許可後にマージしてコードを戻します。以後の変更がある場合は競合や依存関係を確認してください。コードを戻しても保存データは自動では巻き戻りません。既存Volumeを維持し、データの復元は別途判断してください。

## 開発・テスト

- 起動：`npm start`
- テスト：`node --test test/*.test.js`
- 管理者認証：既存の `ADMIN_PASSWORD` を安全な環境設定で使用。値は記録しません。
